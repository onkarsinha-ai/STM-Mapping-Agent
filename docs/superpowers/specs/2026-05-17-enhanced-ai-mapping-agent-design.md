# Enhanced AI Mapping Agent — Design Spec

## Problem Statement

When users select specific source tables (e.g., `public.mappings`, `public.projects`) and a target table (e.g., `public.review_chat_messages`), the AI mapping agent currently:

1. **Ignores table selections** and generates mappings for ALL discovered tables (95+ mappings instead of 6)
2. **Accumulates stale mappings** across multiple generations without clearing old proposals
3. **Lacks guidance for complex data engineering scenarios** (joins, aggregations, derived columns)
4. **Shows all tables in the schema browser** instead of only the selected ones

## Goals

1. Only generate mappings for selected target tables using selected source tables
2. Clear stale proposed mappings before each generation
3. Support complex mapping scenarios: joins, aggregations, derived columns, CASE statements
4. Filter the discovery-phase schema browser to only show selected tables

## Backend Changes

### 1. Universal Table Selection Filtering

**File:** `backend/app/routers/mappings.py`

Current behavior: filtering only applies when `same_db_connection=True`.

New behavior: **Always apply filtering when `selected_source_tables` or `selected_target_tables` exist on the project**, regardless of connection setup.

```python
# Before
has_selections = same_db_connection and (project.selected_source_tables or project.selected_target_tables)

# After
has_selections = bool(
    project.selected_source_tables or project.selected_target_tables
)
```

The `filter_tree` function remains the same but runs unconditionally when selections exist.

### 2. Clear Stale Proposed Mappings

**File:** `backend/app/routers/mappings.py`

Before calling `LLMOrchestrator.propose_mappings`, delete all existing `proposed` status mappings for the project:

```python
from sqlalchemy import delete
from app.models.mapping import Mapping, MappingStatus

await db.execute(
    delete(Mapping).where(
        Mapping.project_id == project_id,
        Mapping.status == MappingStatus.proposed
    )
)
```

This prevents stale mappings from appearing in the review table.

### 3. Enhanced LLM Prompt

**File:** `backend/app/services/llm_orchestrator.py`

Replace the generic prompt with a structured prompt that includes:

- **Hard constraints** (must-follow rules)
- **Scenario examples** (5 built-in examples covering common patterns)
- **Confidence scoring rubric**

#### Hard Constraints

```
CRITICAL RULES — YOU MUST FOLLOW THESE:
1. ONLY generate mappings for target tables and columns explicitly listed in the Target Schema below.
2. ONLY use source tables and columns explicitly listed in the Source Schema below.
3. If a target column has no logical source, set source_table=null and source_column=null.
4. Do NOT invent tables, columns, or data types that are not present in the schemas.
```

#### Scenario Examples

| Scenario | Example |
|----------|---------|
| Direct | `target.users.email ← source.customers.email_address` |
| Join / Multi-source | `target.full_name ← CONCAT(source.users.first_name, ' ', source.users.last_name)` |
| Aggregation | `target.total_revenue ← SUM(source.orders.amount)` |
| Derived / CASE | `target.status ← CASE WHEN source.orders.deleted_at IS NULL THEN 'active' ELSE 'inactive' END` |
| No mapping | `target.id ← null (surrogate key, generated by target system)` |

#### Confidence Rubric

- `0.90–1.00`: Exact name match + same data type
- `0.70–0.89`: Fuzzy name match or compatible type
- `0.50–0.69`: Inferred semantic match or requires transformation
- `< 0.50`: Uncertain; include only if no better option exists

### 4. Output Validation

**File:** `backend/app/services/llm_orchestrator.py`

After parsing the LLM response, validate each proposal:

```python
valid_proposals = []
for prop in proposals:
    target_table = prop.get("target_table", "")
    target_column = prop.get("target_column", "")
    source_table = prop.get("source_table")
    source_column = prop.get("source_column")

    # Skip if target table/column not in filtered target schema
    if not _is_valid_target(target_table, target_column, target_schema):
        continue

    # Skip if source table/column not in filtered source schema (unless null)
    if source_table and not _is_valid_source(source_table, source_column, source_schema):
        continue

    # Cap confidence
    confidence = min(prop.get("confidence_score", 0.5), 1.0)

    valid_proposals.append(prop)
```

## Frontend Changes

### 1. Filtered SchemaBrowser

**File:** `frontend/src/pages/ProjectPage.tsx`

Pass filtered schema to `SchemaBrowser` based on saved selections:

```typescript
const filteredSchema = useMemo(() => {
  if (!sameDbConnection || !hasSelections) return schema;

  const allowed = new Set([
    ...selectedSourceTables,
    selectedTargetTable
  ]);

  const filtered: SchemaTree = {};
  for (const [schemaName, tables] of Object.entries(schema)) {
    for (const [tableName, columns] of Object.entries(tables)) {
      const key = `${schemaName}.${tableName}`;
      if (allowed.has(key)) {
        if (!filtered[schemaName]) filtered[schemaName] = {};
        filtered[schemaName][tableName] = columns;
      }
    }
  }
  return filtered;
}, [schema, sameDbConnection, hasSelections, selectedSourceTables, selectedTargetTable]);
```

Replace `<SchemaBrowser schema={schema} />` with `<SchemaBrowser schema={filteredSchema} />`.

## Data Flow

```
User selects tables → Save Selections → DB updated
                                    ↓
User clicks Generate Proposals → Backend:
  1. Fetch project + selections
  2. Fetch schema cache entries
  3. Filter entries by selections
  4. Delete old proposed mappings
  5. Build enhanced prompt
  6. Call LLM
  7. Validate proposals against filtered schemas
  8. Save valid proposals
                                    ↓
Frontend refreshes → MappingTable shows only relevant mappings
```

## Error Handling

| Scenario | Handling |
|----------|----------|
| LLM returns invalid JSON | Return 502 with parse error detail |
| LLM proposes invalid target table | Silently drop during validation |
| LLM proposes invalid source table | Silently drop during validation |
| No valid proposals after filtering | Return 200 with message "No valid mappings generated" |
| Empty schema after filtering | Return 400 with "No tables match your selections" |
